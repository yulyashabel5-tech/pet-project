# Обзор API

Users API — REST‑сервис для создания, получения, обновления и удаления пользователей.

## Возможности и методы

| Метод | Эндпоинт | Назначение |
| --- | --- | --- |
| `GET` | `/users` | Получить список пользователей (с поддержкой лимита на страницу) |
| `POST` | `/users` | Создать нового пользователя |
| `GET` | `/users/{id}` | Получить информацию о пользователе по ID |
| `PUT` | `/users/{id}` | Полностью обновить данные пользователя |
| `PATCH` | `/users/{id}` | Частично обновить данные пользователя |
| `DELETE` | `/users/{id}` | Удалить пользователя |

## Формат данных

Запросы и ответы передаются в формате JSON. Примеры приведены в справочнике API.

## Серверы API

| Сервер | URL | Назначение |
| --- | --- | --- |
| Основной | `https://api.documentat.io/api/prod` | Реальные данные, используется клиентами |
| Тестовый | `https://api.documentat.io/api/dev` | Для разработки и тестирования |

## HTTP‑коды

| Код | Название | Причина |
| --- | --- | --- |
| `200` | Успешный запрос | Данные успешно получены или обновлены |
| `201` | Пользователь создан | Ответ на `POST /users` |
| `204` | Пользователь удалён | Ответ на `DELETE /users/{id}` |
| `401` | Неавторизованный доступ | Отсутствует или невалиден заголовок `Token` |
| `404` | Не найден ресурс | Пользователь с указанным `{id}` не существует |
| `405` | Данный метод не поддерживается | Например, вызов `PUT` на эндпоинте, где разрешён только `PATCH` |
| `409` | Конфликт при обновлении данных пользователя | Попытка создать пользователя с уже занятым `username` или `email` |
| `422` | Невозможно обработать содержимое запроса | Не прошла валидация: поле не заполнено, неверный тип, значения параметра вне допустимого диапазона |
| `500` | Ошибка сервера | Внутренняя ошибка на стороне API: сбой БД, баг, таймаут |
